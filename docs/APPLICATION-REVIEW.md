# In-app application review

The user-facing workflow follows the Tsenta screens observed live on October 16, 2026: company identity/status header; resume/job-description pane beside preparation progress; a review screen with instructions on the left and grouped fields on the right; submission from within the app. Reference screenshots are in the planning workspace outputs as tsenta-live-resume-processing.png, tsenta-live-application-processing.png and tsenta-live-final-review.png. No action was submitted or changed in Tsenta during observation.

Workspace reads saved `filledSteps[].answers` and overlays the current checkpoint. `fieldsFilled` can contain field-name strings (e.g. `resume`), not question/answer objects; treating it as answers caused the blank review. Password and security-code labels are excluded. Current checkpoint controls can be edited when supported; other saved step fields and custom controls without an enumerated option list are read only. This is not yet full parity with every ATS control Tsenta supports.

Edits use the existing checkpoint-bound answers endpoint. Saving queues revalidation and removes submission approval; it never sends the application. Final submission requires review confirmation, displays the resume/cover letter, checks a fresh state token, and uses existing resume-review/submit endpoints. The backend also rejects optional stale `expectedReview` tokens; older callers retain their existing contract. The currently running main backend predates this guard and needs a controlled restart to activate server-side token checks; frontend checks are live immediately after build. Review requests that change documents can require a fresh attachment check before submission.

The official Quisitive logo is hosted locally from https://quisitive.com/wp-content/uploads/2024/10/cropped-Quisitive-logo-Q-favicon-blue-background-1-1.png. Existing curated SVGs and employer-provided HTTPS logo URLs remain supported; unavailable company assets keep the initials fallback.

Verification: 44 model/application tests and 8 isolated submission scenarios passed; TypeScript and production build passed. Browser verification used a synthetic review application to edit an answer, save it, and observe verification queued without submitting. The live Quisitive application shows 15 answers and remains paused at final review. No Quisitive or Tsenta submission was performed in this UI repair.
